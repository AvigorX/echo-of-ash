# Echoes of Ash

A small, playable top-down action RPG for **Godot 4.7** with **zero imported assets**:
every sprite, tile, light, particle, bar and font is generated by code at runtime.
No network access, no plugins, no third-party libraries.

> **Handoff:** the session checkpoint (what is done, what is missing, how to resume,
> measured pitfalls) is in [`CHECKPOINT.md`](CHECKPOINT.md).

```
Godot 4.7.2.stable.official.ed1daf0bf  ·  GDScript
22 game scripts + 6 test scripts  ·  4,685 lines (1,206 of tests)
world 1536×1536 px (96×96 tiles of 16 px)  ·  internal resolution 480×270  ·  nearest filtering
```

## Quick start

The engine lives in `~/PROGETTI/G-DEV/Godot_v4.7.2-stable_win64.exe/`.
From `~/PROGETTI/G-DEV`:

```bash
ENGINE=./Godot_v4.7.2-stable_win64.exe/Godot_v4.7.2-stable_win64.exe

# play (opens a window at 1440×810, renders 480×270 and scales up ×3)
"$ENGINE" --path projects/echoes-of-ash

# play a specific world
"$ENGINE" --path projects/echoes-of-ash -- --seed 424242

# headless smoke test (no window, exits when the main loop ends)
./Godot_v4.7.2-stable_win64.exe/Godot_v4.7.2-stable_win64_console.exe \
  --headless --path projects/echoes-of-ash --quit-after 120
```

The project is also openable from the Godot editor (`Import` → `project.godot`).
First launch generates the world (≈250 ms) and the ground texture (≈250 ms).

The seed is printed in the HUD (`seed <n> · <phase>`). Default seed: `20261019`.

## Controls

These are the bindings actually implemented and shown in-game (bottom-left of the HUD):

| Input | Action |
|---|---|
| `W A S D` | move in 8 directions |
| mouse | aim the melee attack |
| left mouse button | attack (105° arc, 26 px reach) |
| `E` | interact / collect the highlighted object, advance dialogue, rise again when dead |
| `I` | inventory panel |
| `1` `2` `3` `4` | use or equip the item in that inventory row |
| `ESC` | pause menu (Resume / New world) |
| `R` | regenerate the world with the next seed |

Any mapping change must be made in `project.godot` **and** in the HUD control guide
(`scripts/ui/hud.gd`, `controls_label`).

## What is implemented

### World
- Deterministic procedural island: elevation + moisture value noise, percentile
  thresholds keep the biome mix stable across seeds (≈22 % water, ≈78 % land,
  grass / moss forest floor / sand / dirt / stone / rubble).
- Points of interest (four) connected by BFS paths over land; dirt paths are
  widened irregularly and avoid water.
- Two ruined walled compounds built on a grid around POIs, with path openings.
- ~800 decorations with minimum spacing: trees, rocks, ruin walls (solid,
  collidable), shrubs, mushrooms, pebbles (cosmetic).
- Guaranteed safe spawn: 11×11 cells cleared, all props kept ≥ 4 cells away.
- Terrain, decoration, entities and loot use **separate RNG streams** derived from
  the seed (`WorldGenerator.make_stream(seed, id)`), so cosmetic changes cannot
  move enemies or reshape the land.

### Player
- `CharacterBody2D`, 8-directional movement with acceleration/friction, collision
  against solid props, water is not walkable (axis sliding along the shore).
- `Camera2D` child with smoothing and world limits.
- Procedurally drawn wanderer: idle breathing, walk cycle, facing (8 directions),
  sword pose during the swing, damage blink, death pose.
- Melee attack with cooldown, arc query, hit sparks, knockback, camera shake.
- Health, armour reduction, invulnerability window, damage vignette, death and
  respawn at the last brazier.

### Enemies (two visually distinct types)
| | Cinder Crawler | Ash Warden |
|---|---|---|
| silhouette | low, spiked, crimson | tall, stone, amber core |
| health / damage | 26 / 9 | 72 / 18 |
| speed / detection | 62 / 118 px | 44 / 152 px |
| reward | 12 XP | 34 XP |

States: `IDLE → PATROL → CHASE → WINDUP → RECOVER`, plus `HURT` and `DEAD`.
Movement uses a raycast steering fan + sliding + a 0.6 s stall detector that
forces a lateral sidestep, so they do not stick to walls. Line of sight is a
physics ray: a tree or ruin wall between you and the enemy hides you.
Loot is probabilistic (guaranteed 2 ash shards from a Warden); killed enemies
respawn at their anchor after 28 s **only if the player is more than 260 px away**.

### RPG systems
- XP curve (`30`, then `×1.35 + 8`), levels grant +12 max health and +1.5 damage.
- Inventory with 12 slots, 5 item types, three equipment slots:
  `ash_shard` (resource, also grants 2 XP), `vial_of_sap` (+35 HP),
  `ash_blade` (+4 damage), `warden_plate` (−2 incoming damage),
  `ember_charm` (+20 max health).
- Equipment bonuses are read live by the player, so equipping changes the numbers
  immediately; the HUD refreshes through signals.
- Progression **survives world regeneration**: the player node is reused, only the
  world is rebuilt.

### Interaction
- Unified `Interactable` contract (`prompt_text`, `can_interact`, `interact`).
- The Wanderer NPC with a four-line dialogue, one-time reward (Ember Charm + 20 XP).
- Two braziers: heal 35 HP, 12 s cooldown, set the respawn point, cast light.
- 18 scattered pickups; `E` collects whatever is nearest, with a screen prompt.

### UI (all built in code, `CanvasLayer`)
Health bar, XP bar and level, seed/day-phase readout, control guide, interaction
prompt, fading pickup notifications, inventory panel with descriptions and
equipped marker, pause menu with working buttons, death overlay, damage and
level-up vignettes.

### Atmosphere
Animated water overlay (moving glints and shore foam), drifting fog puffs built
from a generated radial texture, additive torch light with flicker + brazier
lights, `CanvasModulate` day/night cycle (210 s), attack arcs, hit sparks, death
bursts, level-up ring, camera shake, red damage vignette.

## Architecture

```
project.godot                 13 input actions, 480×270 viewport, nearest filter
scenes/main.tscn              one root node: the Game script builds everything else
scripts/
  systems/game.gd             root: world lifecycle, wiring, loot, respawns, input, pause
  systems/day_night.gd        CanvasModulate cycle
  world/world_data.gd         pure grid data + queries + deterministic layout hash
  world/world_generator.gd    procedural generation (no nodes, fully headless-testable)
  world/ground_texture.gd     Image → ImageTexture ground (fill_rect detail)
  world/prop_visual.gd        props + optional StaticBody2D
  world/water_overlay.gd      animated water / foam
  world/fog_layer.gd          generated soft-puff texture, camera-relative drift
  world/light_layer.gd        additive radial glow (generated texture)
  player/player.gd            movement, combat, health, XP, inventory ownership
  player/player_visual.gd     procedural character drawing
  enemies/enemy.gd            FSM, steering, damage, loot hooks, respawn anchor
  enemies/enemy_visual.gd     two silhouettes + telegraph + health bar
  combat/combat.gd            pure melee arc resolution
  combat/effects.gd           slashes, particles, rings
  items/item_db.gd            item definitions (data only)
  items/inventory.gd          inventory + equipment rules (no UI)
  items/pickup.gd             collectible, procedural icon per item kind
  interact/interactable.gd    base contract
  interact/npc.gd             Wanderer
  interact/brazier.gd         heal + respawn point + light
  ui/hud.gd                   every widget, built in code
tests/                        see below
out/                          screenshots produced by tests/capture.gd (.gdignore)
```

Rules followed:

- **Data ↔ presentation separated.** `WorldData`, `WorldGenerator`, `Inventory`,
  `ItemDB`, `Combat` contain no nodes and run headless. `*_visual.gd` only reads
  state and draws.
- **Signals upward, configuration via `@export`/constructor.** The player does not
  know enemies exist: it emits `attack_swing(dir, damage)` and `game.gd` resolves
  the hit. Enemies emit `died`/`struck`; the HUD only observes the player.
- **One owner per concern.** `game.gd` is the composition root and the only place
  that knows all subsystems.
- **Determinism.** Every random decision goes through an explicitly seeded
  `RandomNumberGenerator`; `WorldData.layout_hash()` fingerprints terrain, props,
  spawn anchors, enemies and items.

### Design decisions worth knowing

- **Melee is an arc query, not an `Area2D`.** Measured in this environment:
  `Area2D` overlap after a teleport only registers from the 3rd physics frame, which
  makes combat tests wait arbitrarily and behave inconsistently. Distance + angle
  against the `enemies` group is exact on the first frame and testable headless.
- **Water has no collider per cell.** 2,000 static bodies would cost more than they
  buy; movement is corrected against the grid with axis sliding instead.
- **`y_sort_enabled` on the entity container** gives depth ordering for free; node
  origins sit at the feet of every character and prop.
- **No save file.** Progression is session-scoped, as specified. Persisting it would
  be a JSON file with an explicit version (see next steps).

## World generation and seeds

`WorldGenerator.generate(seed, width=96, height=96)` is pure and deterministic:

1. **Terrain** — three octaves of value noise for elevation, two for moisture,
   bilinear + cubic smoothing, radial falloff so the map is an island. Terrain is
   classified with **percentile thresholds** (22 % water, 7.5 % stone, 36 % moss),
   so every seed has a comparable biome mix instead of a lucky/unlucky distribution.
2. **Spawn** — nearest land patch with clearance to the centre, then an 11×11 cell
   cleared area (water converted to sand, stone to grass, props forbidden).
3. **POIs** — four anchors (near the corners) snapped to land with 7×7 clearance.
4. **Paths** — BFS over land between spawn and each POI, carved as dirt with random
   widening; a straight sand causeway is the fallback if an island is split.
5. **Ruins** — 7×7 walled compounds on two POIs; wall segments on the perimeter with
   gaps where paths enter; rubble floor; solid collision per wall.
6. **Props** — decoration stream; density depends on biome (forest on moss, rocks on
   stone); solid props mark their cell as blocked and a 3×3 "crowded" area.
7. **Entities** — entity stream for 17 crawlers + 7 wardens (≥ 11 cells from spawn,
   wardens ≥ 15), loot stream for 18 items.

**Streams** are `make_stream(seed, id)`: `1` terrain, `2` decoration, `3` entities,
`4` loot (generation), `7` ground texture detail, `9` runtime loot rolls.
Changing how many numbers the decoration stream consumes cannot shift a single
enemy, because it never shares a generator with them.

**Seeds:**

- default `20261019` (`Game.DEFAULT_SEED`);
- CLI: `-- --seed 424242`;
- `R` (or pause → *New world*) regenerates with `seed + 1` and keeps your progression;
- the same seed always rebuilds the same world: verified by comparing
  `WorldData.layout_hash()` across separate generations and at runtime.

## Known limitations

1. **No audio.** No procedural sound effects or music yet.
2. **No save file.** Closing the game loses progression (session-only, as specified).
3. **Chunk streaming is designed for but not implemented.** The world is one
   deterministic grid of 96×96 cells; the field functions are per-cell and stream-based,
   so chunking can reuse them, but there is no loader/unloader yet.
4. **One map size.** 96×96 tiles is fixed for the prototype; generation accepts other
   sizes but the content tuning (24 enemies, 18 items) is not scaled.
5. **Enemy pathfinding is local.** Raycast steering + sidestep avoids obstacles but does
   not plan routes around long walls; a distant target behind a large ruin may take a
   while. No `NavigationAgent2D` (it is awkward headless and unnecessary at this scale).
6. **Inventory panel lists 8 rows** (12 slots exist); overflow is visible only by
   scrolling-free truncation. No drag & drop, no item comparison.
7. **Damage feedback is numeric only in the HUD/logs**, there are no floating damage
   numbers over enemies.
8. **Lighting is additive 2D glow**, no shadows or occlusion; night visibility depends
   on the torch radius.
9. **Enemy respawn re-uses the anchor cell**; if the player rebuilds the situation, a
   respawned enemy can appear in view (it is skipped while the player is within 260 px).
10. **`R` is destructive**: progress is kept but the world, enemies and uncollected loot
    are replaced immediately.

## Recommended next steps

1. Procedural audio (`AudioStreamGenerator`): footsteps, hit, death, brazier hum, ambience.
2. Versioned save file (`user://save.json`, `{"version": 1, ...}`) with validation and a
   safe fallback; load/save tests in headless.
3. Chunk-based world streaming around the camera, reusing `WorldGenerator` fields.
4. Enemy variety: a ranged "Ember Wisp" with projectiles, and a Warden variant with a
   telegraphed ground slam.
5. Floating damage numbers and hit-stop (2–3 frames) for combat weight.
6. Item usability: a hotbar, item comparison, and a merchant trade (shards → vials).
7. Map screen and a compass to the nearest brazier.
8. Difficulty curve: scale enemy stats by distance from spawn.
9. Options: input remapping UI, screen shake intensity, colour-blind friendly palettes.
10. Export presets for Windows/Linux and a CI job running the three test suites.
